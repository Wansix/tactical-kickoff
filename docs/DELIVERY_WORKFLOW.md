# Tactical Kickoff 개발·검증 게이트

## 운영 원칙

재미 검증보다 먼저 기본 기능과 실제 플레이가 통과되어야 한다.

```text
개발팀 구현
→ 검증팀 자동·브라우저 검증
→ 실패 수정
→ Tech Lead 실제 플레이 최종 승인
→ 승인 후 main 반영/배포
```

## 개발팀

- 시뮬레이션 규칙과 UI를 수정한다.
- 새 기능은 재현 가능한 테스트를 함께 추가한다.
- `npm test`, `npm run typecheck`, `npm run build`를 실행한다.
- 기능 브랜치에서 작업하고 `main`에 직접 푸시하지 않는다.

## 검증팀

### 자동 검증

- 상태 전이: `READY → RUNNING → PAUSED → RUNNING`
- `RESTART/REPLAY`가 점수·시간·위치를 초기화하는지
- 속도 선택과 역할 교대
- 골 판정·공 리셋·90초 종료
- 선수 도형 ID와 최소 간격
- 같은 슬롯/역할의 양 팀 shape가 동일하고 팀 색상만 다른지
- Striker와 Anchor가 모두 장시간 이동하는지
- 공의 이동 범위가 중앙에 고착되지 않는지
- 60초 안에 최소 1회 이상 유효한 골 진행이 발생하는지
- 두 Striker의 반복 중앙 킥만으로 경기가 진행되지 않는지
- `npm test`
- `npm run typecheck`
- `npm run build`

### 브라우저 검증

- 실제 URL 또는 로컬 Vite URL에서 Phaser가 부팅되는지
- 콘솔 오류가 없는지
- START 후 공·선수가 움직이는지
- PAUSE 후 공·선수가 멈추는지
- RESTART 후 초기 화면으로 돌아오는지
- 세로 경기장, 위·아래 골대, 선수 도형과 라벨이 잘리지 않는지
- 일반 모바일 폭, Fold 접은 폭, Fold 펼친 폭에서 가로 스크롤이 없는지
- 회전 후 캔버스와 컨트롤이 재배치되는지
- 터치 버튼 최소 44px인지

### 실제 게임플레이 검증

자동 테스트가 통과해도 아래 실제 플레이 계약을 별도로 확인한다.

- Striker는 공을 추적하되 공 위에 겹쳐 고정되지 않고 공격 방향으로 전진한다.
- Anchor는 고정 lane에 도달한 뒤에도 공과 상대 위치 변화에 반응한다.
- 한 tick에는 한 선수만 공에 개입하며, 동일 조건에서는 거리·역할·ID 순으로 승자가 결정된다.
- 킥 직후에는 짧은 cooldown이 적용되어 두 Striker가 즉시 공을 되돌려 치지 않는다.
- 공은 Blue 위쪽, Orange 아래쪽 골문 방향으로 진행할 기회를 가진다.
- 중앙에서 30초 이상 공이 정체되거나 0-0으로 고착되면 실패로 기록한다.
- 실제 플레이 증거는 시작 프레임, 중간 움직임, 득점/공격 전개, PAUSE, RESTART를 포함한다.

## Tech Lead 최종 게이트

다음 조건을 모두 통과해야 실제 플레이 승인이다.

- 자동 테스트 통과
- typecheck/build 통과
- 브라우저 콘솔 오류 없음
- 실제 START/PAUSE/RESTART 플레이 통과
- 세로 화면에서 공·선수·골대가 모두 보임
- 선수 도형이 서로 구분됨
- 같은 역할은 양 팀에서 같은 도형이고, 팀은 색상으로 구분됨
- 60초 실제 시뮬레이션에서 양 역할 이동·공격 전개·골 진행이 확인됨
- 주요 라벨이 겹치지 않음
- `git diff --check` 통과
- 현재 브랜치·커밋·배포 대상이 명확함

하나라도 실패하면 재미·밸런스 검증으로 넘어가지 않고 기본 기능 수정 단계로 돌아간다.

## 현재 결정

- 모바일 우선 세로 경기장: simulation field `540×960`
- Blue는 아래에서 위로 공격
- Orange는 위에서 아래로 공격
- 역할별 도형: Striker=원, Anchor=네모. 팀은 색상으로 구분
- 세로 좌표계를 유지하고, 화면 폭에 맞춰 Phaser `FIT` scaling 적용
- Telemetry는 게임판보다 우선하지 않도록 보조 영역으로 유지
